# 深海观测缆 · 站间偏移校核台

检修期间工程师在浏览器粘贴脚本（最多 **64 个站点、180 行**），依次
登记 / 撤回站间整数偏移关系 `x_v − x_u = d`，并在检查点确认当时仍活动的
读数能否共同成立。冲突时按关系标识稳定选出矛盾环，展示环中各式相加得到的
**推导值**与登记关系的**冲突值**，可逐项复算。

既有校核完成后，工程师还可在任意**冲突检查点**上发起**最小停用集审计**：
找出停用哪些“当时活动的关系”后，其余读数**首次**能够共同成立。审计为独立
结论，不改写原脚本与原检查点结果；仅受理活动关系 **≤ 18 条**的冲突检查点，
超出时明确拒绝。

## 快速开始

```bash
# 默认宿主机端口 8080
docker compose up web

# 可配置宿主机端口
WEB_PORT=9090 docker compose up web
# 打开 http://localhost:9090 ，健康状态 http://localhost:9090/healthz
```

## 一次性验收服务 verify

```bash
docker compose build
WEB_PORT=8080 docker compose run verify   # 退出码 0 = 验收通过，1 = 失败
```

`verify` 依次执行并以退出码报告结果：

1. **复现业务场景**：登记 `A→B=5`、`B→C=-2` ⇒ 可行且推导 `A→C=3`；
   再登记 `A→C=4` ⇒ 展示推导值 3 与冲突值 4 的矛盾环（环内各式逐项相加
   复算）；撤回该关系后下一检查点恢复可行；在该冲突检查点上发起最小停用集
   审计 ⇒ 最少停用 1 条、同层标识升序取 `{r1}`，给出保留关系 `{r2,r3}` 的
   可行势值与各层命中矛盾环；19 条活动关系超上限被明确拒绝。
2. **Compose 页面操作**：以真实页面脚本驱动，完成示例冲突审计；并验证
   活动关系超 18 条上限被拒绝、切换检查点 / 编辑脚本 / 重新校核时旧审计
   立即失效、迟到计算不覆盖当前选择；登记 / 撤回 / 普通检查点显示保持原样。
3. **代码测试**：`node --test test/`（解析器、带势并查集、分治求解、稳定选环、
   最小停用集审计的真实矛盾环 / 逐层剪枝 / 朴素预言机对照）。
4. **构建产物检查**：生成 `dist/`，校验 sha256 清单与页面资源引用。
5. **HTTP 冒烟**：对容器网络 `http://web:8080` 与宿主机映射端口
   `http://host.docker.internal:${WEB_PORT}` 请求 `/`、`/healthz`、
   `/js/solver.js`，确认页面与健康状态可达后退出。

## 脚本文法

| 语句 | 含义 |
| --- | --- |
| `stations: A,B,C` | 可选，至多一行，显式声明站点（≤64） |
| `[id:] A→B=5` | 登记关系 `x_B − x_A = 5`（`->` 与 `→` 等价；省略 id 自动编号 `#1`） |
| `withdraw id` | 撤回关系（亦接受 `撤回 id` / `drop id`） |
| `checkpoint` | 检查点（亦接受 `检查点` / `cp`） |

- 标识：`^[A-Za-z_][A-Za-z0-9_-]{0,31}$`
- 整数范围：±9007199254740991；空行与 `#` 注释行忽略。
- **一次性定位全部问题**：重复登记、未知/已撤回标识、无效标识、未知端点、
  非整数/超界整数、超 64 站点、超 180 行，在一次校核中全部标出，
  并清除旧审计结果（页面提示“旧审计结果已清除”）。

示例：

```
stations: A,B,C
r1: A→B=5
r2: B→C=-2
checkpoint
r3: A→C=4
checkpoint
withdraw r3
checkpoint
```

## 算法（后台不逐检查点重扫活动关系）

1. 每条“登记—撤回”关系换算为在检查点时间轴上的活动区间 `[l,r]`；
2. 区间挂到检查点线段树的 O(log K) 个节点（**时间区间分治**）；
3. DFS 线段树，进入节点并入**可回滚带势并查集**：
   - 按大小合并、不做路径压缩，`pot[x] = value(x) − value(parent[x])`；
   - 合并已连通两端时，若势推出的偏移与登记值不符即得到矛盾环；
   - 离开节点按快照恢复 parent/size/pot/link；
4. 总复杂度 O((E+K) log K · α)，稳定选环规则：节点内按登记行号升序贪心并入，
   候选矛盾环中取**关系标识最小**者。

## 最小停用集审计（仅冲突检查点，活动关系 ≤ 18 条）

审计回答“停用哪些**当时活动**的关系，其余读数**首次**能够共同成立”。
它不改动脚本与既有检查点结论；撤回关系与尚未登记的关系都不在受理集合内。

1. **状态 = 一个停用集合**；判定时用**可回滚带势并查集**按登记行号升序把未停用
   关系全部重建并入，读取可行势值后按快照回滚——同一并查集跨所有状态复用，
   不另起求解；
2. 状态仍矛盾时，并查集同时维护只含“真正合并过分量的原始关系”的**可回滚生成
   森林**，矛盾环取森林中两端点间的唯一**简单路径**（真实边环，不重复、不遗漏
   被按大小合并折叠的关系）；下一条待停用关系**只能从当前矛盾环的环内关系
   （含闭合关系）分支选择**，不能按某个环直接删边、不做贪心；
3. **逐层穷尽**：k = 1, 2, …，第 k 层只接受恰停用 k 条的可行状态；同层候选按
   关系标识升序全部展开，同一停用集只评估一次；
4. **按层下界剪枝**：状态处命中的全部矛盾环共生于同一相容森林，贪心取一组边
   互不相交的环，其数量即“至少还要停用的条数”下界，`depth + 下界 > k` 即剪枝；
   因此绝不枚举全部子集（18 条上限下实际评估数远小于 2¹⁸）；
5. 先保证停用条数最少；同层可行停用集再按关系标识升序逐项比较，取整个集合
   字典序最小者；页面展示最终停用 / 保留关系、保留关系的一组可行势值
   （整体平移任意常数仍为解）与各层命中的矛盾环；
6. 编辑脚本、重新校核或切换检查点时，页面令牌立即作废旧审计；异步计算返回后
   令牌不匹配即丢弃，迟到结果不会覆盖当前选择。

## 目录

```
web/            静态页面（index.html / css / js：parser、solver、app）
test/           node --test 单元测试（含 minaudit.test.js 审计对照）
tools/build.mjs 产物构建与清单校验
verify/         一次性验收服务（verify.mjs / page-flow.mjs 页面操作 / dom-shim.mjs）
deploy/         nginx 配置（含 /healthz）
Dockerfile.web / Dockerfile.verify / docker-compose.yml
```

本地开发（无需容器）：

```bash
node --test test/         # 测试
node tools/build.mjs      # 构建到 dist/
node tools/build.mjs --check
```
